# I-ITSM — P4 Execution Framework

Owner: P4 (Sid). Companion to `PROJECT.md` and `P4_SPEC.md`. Written 9 Nov 2026.
`P4_SPEC.md` says **what** to build. This file says **how** the P4 code is structured and integrated, and the order to build it in, so the work can start today without waiting on P1/P2.

---

## 0. Guiding principles

1. **Ports and adapters.** All P4 logic depends only on Protocols in `app/p4_contracts.py`. P1/P2 code plugs in behind them later. Until then, in-memory fakes implement the same Protocols.
2. **Pure core, thin shell.** Each feature is split into:
   - a **pure decision function or class**: no I/O, `now` injected, unit-tested exhaustively;
   - a **thin runner**: fetches data, calls the decision, applies the result through `IncidentService`.
   The decision code is where the business rules and edge cases live. The runner only handles I/O and errors.
3. **P4 never mutates state directly.** Every effect goes through `IncidentService` (P1/P2), so audit and notification events always fire. P4 code decides *whether* to act; P1/P2 code decides *how*.
4. **Graceful degradation.** An intelligence failure must never break incident creation. Missing model → Null Object. Embedder error → logged and skipped.
5. **One integration point.** P4 exposes a single `wire_p4(app_state, bus, settings, uow_factory)` that P2's `main.py` lifespan calls. This keeps merge conflicts down.

## 3. Background-jobs framework

### 3.1 `BatchJob`: Template Method (an additional named pattern for the report)

```python
@dataclass(frozen=True)
class JobResult:
    job: str
    started_at: datetime
    scanned: int = 0
    actions: Counter[str] = field(default_factory=Counter)   # e.g. {"response_breach": 2}
    errors: list[tuple[UUID, str]] = field(default_factory=list)

class BatchJob(ABC, Generic[T]):
    name: ClassVar[str]

    def run(self, now: datetime) -> JobResult:          # template method: final, not overridden
        assert now.tzinfo is not None
        result = JobResult(self.name, now)
        for item in self.select(now):                   # hook 1
            result.scanned += 1
            try:
                for action in self.process(item, now):  # hook 2: yields action labels
                    result.actions[action] += 1
            except Exception as exc:                    # one bad incident never aborts the batch (test 7)
                log.exception("job=%s incident=%s failed", self.name, item.id)
                result.errors.append((item.id, repr(exc)))
        return result

    @abstractmethod
    def select(self, now: datetime) -> Iterable[T]: ...
    @abstractmethod
    def process(self, item: T, now: datetime) -> Iterable[str]: ...
```

The spec's plain functions stay as one-line facades:
`run_sla_monitor(now, repo, svc, cfg) = SLAMonitorJob(repo, svc, SLAEvaluator(cfg)).run(now)`.

### 3.2 SLA monitor

**Pure core: `SLAEvaluator.evaluate(incident, now) -> list[SLASignal]`**, where `SLASignal = (kind: RESPONSE|RESOLUTION, level: WARNING|BREACH)`.

| Rule | Check |
|---|---|
| Response applies | `acknowledged_at is None` and status is open |
| Resolution applies | status not in {RESOLVED, VERIFIED, CLOSED} and not AWAITING_INFO (G3) |
| Breach | `deadline < now` (strict `<`, so missed ticks are caught on the next run: test 3) |
| Warning | not breached and `deadline - now <= SLA_WARNING_FRACTION × (deadline - created_at)` |
| Both at once | breach supersedes warning (G9) |

**Runner `SLAMonitorJob`:** `select` returns open incidents whose deadline is before `now + max warning horizon`. `process` maps each signal to `svc.mark_sla_warning` or `svc.mark_sla_breach`. Idempotency lives in the service (the methods return `False` if the signal is already recorded), and the job counts only `True` results. That gives test 2 for free.

### 3.3 Escalation

**Pure core: `EscalationPolicy.is_due(incident, now) -> bool`.** True when priority is in `ESCALATION_AFTER_MINUTES`, the incident is unacknowledged, and `now - (last_escalated_at or created_at) >= threshold`.

**Runner `process`:**
1. `fresh = repo.get(id)`, then re-check `is_due(fresh, now)` (test 9).
2. `target = directory.next_in_chain(fresh.escalation_level)`.
3. If `target is None`: `svc.mark_escalation_exhausted(id)`, yield `"exhausted"` only if it returns `True` (test 10).
4. Otherwise `svc.escalate(id, target, level+1, expected_level=fresh.escalation_level)` (G5).
5. Inactive users are skipped inside `next_in_chain` (test 11 lives in the contract suite).

### 3.4 Auto-close

`select = repo.resolved_before(now - timedelta(days=AUTO_CLOSE_DAYS))` (this uses `resolved_at`, G1). `process` re-reads the incident, confirms it is still RESOLVED, then calls `svc.auto_close(id)`. The system actor is supplied by the service.

### 3.5 `SchedulerManager`

```python
class SchedulerManager:
    def __init__(self, settings, uow_factory, clock=utc_now): ...
    def register(self, job_factory: Callable[[UnitOfWork], BatchJob], seconds: int): ...
    def start(self) / shutdown(self)        # called from the lifespan via wire_p4
    def run_now(self, name: str) -> JobResult   # used by the demo/admin endpoint and integration tests
```

- Each tick opens a **fresh DB session (unit of work)**, builds the job, calls `job.run(clock())`, commits, and closes. Sessions are never shared across ticks.
- APScheduler options: `max_instances=1`, `coalesce=True`, `misfire_grace_time=interval`. The job code is synchronous (SQLAlchemy sync), so it runs in the threadpool; it never blocks the event loop.
- `SCHEDULER_ENABLED=false` in tests and on all but one replica. Note in the report that multi-replica deployments need a leader lock or Celery beat.
- Last `JobResult` per job is kept in memory and exposed through `FeatureRegistry`, so the "SLA monitor visible" demo step (workflow 2) has something to show.
- **Demo endpoint (ask P2):** `POST /admin/jobs/{name}/run` → `run_now`. Waiting 5 minutes for a breach on camera is wasteful.

## 4. Intelligence framework

### 4.1 Class design

```
Embedder (ABC)                     Categorizer (ABC)                  EmbeddingStore (Protocol, P2)
 ├─ MiniLMEmbedder (lazy singleton) ├─ SklearnCategorizer (joblib)
 └─ HashingEmbedder (tests/CI)      └─ NullCategorizer (Null Object: always None)

DuplicateDetector(cfg)      score(a_vec, b_vec, same_service) -> float
                            match(new, candidates, vecs) -> list[Match]      # pure
Correlator                  clusters(links, window) -> list[set[UUID]]       # union-find, pure
ResolutionIndex             rebuild(items), query(vec, k, min_sim, category) # numpy brute force
IntelligenceListener        on_created(evt), on_resolved(evt)                # Observer
FeatureRegistry             status() -> {feature: enabled, reason, last_error}
```

### 4.2 Event flow

```
IncidentCreated ──► IntelligenceListener.on_created
                      1. text = incident_text(...)            (skipped if empty)
                      2. vec = embedder.encode([text])[0];  store.save(id, vec)
                      3. duplicates: candidates = repo.open_since(now - window) minus self
                         len(desc) < DUP_MIN_CHARS → fallback rule (same service + category)
                         for each match ≥ DUP_THRESHOLD → svc.link_related(a, b, score)
                      4. category = categorizer.predict(text) → if not None: svc.set_suggested_category
IncidentResolved ─► on_resolved → resolution_index.add(id, vec, category, text)
startup          ─► resolution_index.rebuild(repo.resolved_with_text()); embedder warm-up
```

- **Isolation:** each step sits in its own `try/except` and reports failures to `FeatureRegistry`. Step 3 failing doesn't stop step 4.
- **Latency:** the listener hands work to a single-worker `ThreadPoolExecutor`, so `POST /incidents` doesn't wait on the model. The tests use a synchronous executor so the results are deterministic.
- **Model loading:** `MiniLMEmbedder` loads once (lock-guarded) and is warmed up in the lifespan, so the first report in the demo doesn't stall.

### 4.3 Test vs real embedder

Unit tests use `HashingEmbedder` (deterministic, no download), which is enough for testing windowing, thresholds, the fallback rule and error paths. Tests that depend on **meaning** (13 paraphrase, 16 hard negative) use the real model under `@pytest.mark.model`. CI caches `~/.cache/huggingface` so those still run on every push.

## 5. Evaluation pipeline (numbers the report may quote)

```
gen_synthetic.py (seed=42) ─► data/synthetic_incidents.jsonl ─► train_categorizer.py ─► models/categorizer.joblib
                          └► data/duplicate_pairs.jsonl     ─► eval_categorizer.py  ─► docs/metrics/categorizer.{json,md}
                                (dev / test split)          ─► eval_duplicates.py   ─► docs/metrics/duplicates.{json,md}
```

- **Duplicates:** sweep thresholds on the **dev** split, pick the threshold that maximises F1 (or precision at recall ≥ X; state which), then report precision/recall on the **test** split once. Write the chosen value back as the `DUP_THRESHOLD` default.
- **Categorizer:** stratified split, per-class P/R/F1 plus a confusion matrix (PNG for the report).
- One command regenerates everything: `make metrics`. The report quotes only `docs/metrics/*`.

## 6. Test framework (test lead role)

### 6.1 Fixtures (`tests/conftest.py`)

| Fixture | Provides |
|---|---|
| `t0` | Fixed aware UTC datetime; `travel(delta)` helper via `time-machine` |
| `settings` | `Settings` override with small, explicit thresholds |
| `make_incident(**kw)` | Factory producing `IncidentView` with sane defaults relative to `t0` |
| `repo`, `svc`, `directory`, `store` | Fakes from `tests/fakes/`; `svc` records calls and enforces idempotency |
| `pg_session` | Integration only: real Postgres, transaction rolled back per test |

### 6.2 Contract tests keep the fakes honest

`tests/contract/test_incident_repository.py` is parametrised over `[FakeIncidentRepository, SqlAlchemyIncidentRepository]`. When P2's repository lands, it runs against the same assertions. If a fake drifts from the real behaviour, CI fails, which prevents the "passes with fakes, breaks in docker" failure mode on 17 Nov.

### 6.3 Markers and CI lanes

`unit` (default, no DB), `integration` (Postgres service container), `model` (MiniLM, cached). CI runs all three; locally `pytest -m unit` takes seconds.

### 6.4 Formal test catalogue for the report

Every formal case carries metadata:

```python

                  desc="Scheduler down across deadline", expected="Breach caught on first run")
def test_missed_tick_catch_up(...): ...
```

`scripts/export_test_cases.py` collects the markers from **all members' tests** (`pytest --collect-only` plus a plugin hook) together with the pass/fail status from the JUnit XML. It writes `docs/testing/cases.md`, which is the testing chapter table. Ask P1/P2/P3 to tag their tests the same way by 15 Nov. ## 8. Seed data designed for the demo

`seed.py` is idempotent: upsert by natural key (email, service name, service × priority). It computes timestamps **relative to now at run time**, so the demo always shows live states:

- 1 P1 just created, unacknowledged → escalates within minutes (workflow 3)
- 1 incident at about 85% of its response window → warning on the next tick
- 1 already breached; 1 in AWAITING_INFO (paused clock visible)
- 3–4 paraphrased "payment gateway down" reports on the same service → cluster (workflow 3)
- 1 RESOLVED past `AUTO_CLOSE_DAYS` → auto-closed on the first tick
- About 30 resolved incidents with resolution text, so suggested resolutions have history
